# solon-ai-agent 国际化（i18n）

从 4.2 起，solon-ai-agent 中面向模型和用户的文案（主提示词、团队协议、运行时提示、上下文压缩、工具描述）统一放在 solon-i18n 资源包里，内置中文（zh）和英文（en）。

## 1. 指定语言

```java
// ReAct
ReActAgent.of(chatModel).locale(Locale.ENGLISH).build();
agent.prompt("...").options(o -> o.locale(Locale.ENGLISH)).call();

// Team
TeamAgent.of(chatModel).locale(Locale.ENGLISH).build();
team.prompt("...").options(o -> o.locale(Locale.ENGLISH)).call();

// Simple
SimpleAgent.of(chatModel).locale(Locale.ENGLISH).build();
```

语言的决定顺序：

```
options.locale（显式设置） > 所在团队的语言（作为团队成员时继承） > AgentI18n.getDefaultLocale()（默认中文）
```

团队成员（ReAct、Simple、嵌套 Team）没有显式设置 locale 时，自动继承所在团队的语言，因此 `TeamAgent...locale(Locale.ENGLISH)` 会让主管和成员都使用英文；成员显式设置的 locale 仍然优先。

语言只有一个来源：配置。4.2 删除了 `AgentSystemPrompt.getLocale()` —— 模板自带语言不可配置，会让 `options.locale` 之外多出一个语言来源，正是提示词与协议指令中英混排的根因。模板现在只负责“按给定语言渲染”，同一个模板实例在不同请求上可以输出不同语言；需要固定语言时在智能体或请求上设置 `locale(...)`。

随之移除的两个“语言预设”类：`ReActSystemPromptCn/En`、`TeamSystemPromptCn/En`（它们唯一的作用就是让模板自带语言）。迁移：`systemPrompt(ReActSystemPromptEn.getDefault())` → 默认模板 + `locale(Locale.ENGLISH)`。

主提示词、协议指令、运行时提示、压缩提示统一只读 `trace.getOptions().getLocale()`，因此设置一处就能切换全部文案，不会出现中英混排。

全局默认语言可以修改：

```java
AgentI18n.setDefaultLocale(Locale.ENGLISH);
```

## 2. 资源包

| 内容包 | 文件 | 范围 |
|---|---|---|
| `solon-ai-agent.i18n.react` | `solon-ai-agent/i18n/react*.yml` | ReAct / Simple 主提示词、推理反思、计划、HITL、反馈工具 |
| `solon-ai-agent.i18n.team` | `solon-ai-agent/i18n/team*.yml` | Team 主提示词、协议基类、A2A、Swarm、Sequential、主管、AgentProfile |
| `solon-ai-agent.i18n.team-protocol` | `solon-ai-agent/i18n/team-protocol*.yml` | Hierarchical、Blackboard、ContractNet、MarketBased |
| `solon-ai-agent.i18n.compress` | `solon-ai-agent/i18n/compress*.yml` | 上下文压缩策略 |

- 默认文件（无后缀）是英文，作为所有语言的兜底；`_zh` 是中文（`zh_CN`、`zh_TW` 都会命中）。
- 加载顺序为 默认文件 → `_语言` → `_语言_国家`，后加载的覆盖先加载的。
- 每一层先找 `.properties`、找不到再找 `.yml`；**同一层只用找到的第一个文件**。内置资源是 `.yml`。

### 扩展新语言或覆盖文案

在自己的类路径下放置同名文件即可：

```
src/main/resources/solon-ai-agent/i18n/react_ja.yml     # 新增日文
src/main/resources/solon-ai-agent/i18n/team_zh_CN.yml   # 只覆盖个别 key
```

注意：用户文件与内置文件同名（如也叫 `team_zh`）时，会**整个替换**内置的那一层，不是按 key 合并。缺少的 key 不会报错，而是落回默认文件的英文，形成中英混排。只覆盖个别 key 时请用更细的一层（`_zh_CN`）或覆盖工厂。

也可以设置智能体专用的覆盖工厂（只影响智能体，不影响应用自身的 `I18nUtil`）。内置资源始终作为底层，工厂返回的文案只覆盖同名 key，缺失的 key 自动落回内置文案；工厂返回 null 或抛异常时也落回内置文案：

```java
AgentI18n.setBundleFactory((bundleName, locale) -> new MyBundle(bundleName, locale)); // 传 null 取消覆盖
```

工厂在缓存锁外调用（可以访问远程服务），也可以回调 `AgentI18n` 读取**其它**语言（如以英文为底稿）；读取正在加载的同一语言会快速失败，并按“工厂抛异常”处理（告警、落回内置文案）。加载期间若调用了 `setBundleFactory` / `clearCache`，这次加载的结果不会写入缓存。

### 编写资源文本的约束

资源为 yml，每个值都写成扁平 key 的 `|-` 块标量，**只写正文**：

```yaml
team.prompt.task: |-
  ## 当前任务
  {task}
react.prompt.classic.tools.schema: |-
  参数定义:
```

- **值的首尾不留换行或空格**：段落之间的换行、标签前后的空格等分隔符由调用处的代码负责（如 `sb.append("\n").append(AgentI18n.get(...)).append("\n")`）。因此扩展语言（如 `_ja.yml`）或覆盖个别 key 时，只需翻译正文，不必关心空白；值原样使用，加载时不做任何字符转换。正文中间的换行直接换行书写。
- **一句话放在一个 key 里**：不要把一句话拆成多个 key 再由代码拼接（各语言的语序、句间是否有空格都不同）。例如“角色 + ReAct 范式”合为 `react.prompt.intro.text` / `react.prompt.intro.native`，计划看板的“正常推进 + 结尾说明”合为 `react.plan.board.advance.last` / `.next`。
- **key 统一在 `AgentI18nKeys` 中管理**：常量名 = key 转大写、`.` 换成 `_`（如 `team.prompt.role` → `AgentI18nKeys.TEAM_PROMPT_ROLE`），带占位符的常量在注释里列出变量名。产品代码只通过常量取文案，不写 key 字面量。新增 key 时在中英 yml 和 `AgentI18nKeys` 中同时加，并补一个走到该调用点的用例（见 §6 key 覆盖率）。用户覆盖或扩展语言时，也以该类列出的 key 为准。
- **占位符只用命名形式** `{name}`（字母、数字、下划线，数字不开头），Java 侧：
  ```java
  AgentI18n.get(locale, AgentI18nKeys.TEAM_PROMPT_MEMBERS_TITLE);
  AgentI18n.fmt(locale, AgentI18nKeys.REACT_PROMPT_INTRO_TEXT, "role", role);
  AgentI18n.fmt(locale, AgentI18nKeys.REACT_STOPLOOP_PROMPT, "window", windowSize, "count", count);
  AgentI18n.fmt(locale, AgentI18nKeys.TEAM_BASE_SUPERVISOR_PROTOCOL, "protocol", p, "candidates", c, "finishMarker", m);
  AgentI18n.fmt(locale, key, vars); // Map<String, ?>
  ```
  单次线性扫描、只替换传入的名字，变量内容不会被二次替换。只有形如 `{[A-Za-z_][A-Za-z0-9_]*}`、名字不超过 64 个字符的才算占位符（与 lint 规则一致）；JSON 示例（`{"name": ...}`、`{...}`）、`{0}`、`{a b}` 之类的形式以及未传入的名字一律原样保留。变量值为 null 时输出 `null`（与字符串拼接一致）。`fmt` 的变量名重复时抛 `IllegalArgumentException`。不走 MessageFormat，也不走表达式引擎（文案是数据，不求值）。
- 禁止出现 `${` 和 `#{`：提示词会经过 SnEL 模板渲染。
- 禁止行首 `---`（配置加载器会当作文档分隔），禁止 `solon.env*` 这类 key；缩进 2 空格、不用 Tab、不嵌套 key。
- 各语言的 key 集合、以及每个 key 的占位符名字必须完全一致。
- 值的首尾不得有空白，也不得出现旧的空白标记符（`⏎` U+23CE、`␣` U+2423）。

以上规则由 `I18nResourceLintTest` 校验（含 `AgentI18nKeys` 与资源 key 集合一致、常量命名、无未使用常量、产品代码无 key 字面量；源码调用点：`get` / `fmt` 的 key 必须是常量，`fmt` 传入的变量名必须与占位符一致且不重复，`get` 取的文案不得含占位符）。

## 3. 不做国际化的内容

以下内容属于解析协议，保持常量：`finishMarker`、`Thought:` / `Action:` / `Final Answer:` / `Observation:`、工具名、JSON 字段名，以及日志和异常消息。

参与逻辑判断的文案与关键词，会在**所有已知语言**中合并识别（内置 zh/en + 已使用过的语言 + `AgentI18n.registerLocale` 登记的语言 + 默认语言），会话中途切换语言也不受影响。新增语言只需要加资源文件，不用改代码：

| 判断 | 位置 | 资源 key |
|---|---|---|
| 压缩的"无增量"标记 | `CompressionUtil.isEmptySummary` | `compress.llm.empty_marker`、`compress.keyinfo.empty_marker` |
| 分层压缩的摘要前缀 | `HierarchicalCompressionStrategy.isSummaryContent` | 摘要前缀 key |
| 向量归档标记 | `VectorStoreCompressionStrategy.isArchivedNotice` | `compress.vector.archived_tag` |
| ContractNet 的招标意图 | `ContractNetProtocol.isExplicitBiddingDecision` | `protocol.contractnet.bidding_keywords` |
| Blackboard 的完成语义 | `hasCompletedKeyword` | `protocol.blackboard.completed_keywords` |
| 主管决策中的指派动词 | `SupervisorTask.extractAssignedAgentName` | `team.supervisor.assign_verbs`（正则备选项） |

关键词类 key 的值以 `|` 分隔多个条目，条目内不能含 `|`；`team.supervisor.assign_verbs` 的条目是正则片段，长词放在前面。

从 Redis/File 恢复旧会话时，智能体会在每次执行的准备阶段自动登记快照中携带的语言（`AgentI18n.registerLocaleOf`），旧消息里的标记能被识别，**无需手动调用 `registerLocale`**。仅当自定义 `Trace` 或自行拼接历史时需主动登记：

```java
AgentI18n.registerLocale(locale);
```

## 4. Talent 中获取语言

Talent 拿不到 trace。ReAct 在激活 Talent 前，会把请求语言写入 `Prompt.attrs` 的 `AgentI18n.ATTR_LOCALE`，Talent 可以这样读取：

```java
Locale locale = AgentI18n.localeOf(prompt);
```

写入时请用 `AgentI18n.putLocale(prompt, locale)`：它存的是语言标签字符串（如 `en`、`zh-CN`），**不要直接存 `Locale` 对象**，否则会话快照（Redis/File）无法反序列化还原。`localeOf` 同时兼容字符串和 `Locale`。

作为团队成员运行时，`Agent.run` 也会把团队语言写入交给成员的 prompt，自定义 `Agent` 实现可以用同样方式读取。

## 5. 兼容性说明

- 新增依赖 `solon-i18n`。它会注册一个只解析请求 locale 的路由过滤器 `I18nFilter`，没有其它副作用。内置资源为 yml，由 `solon-ai-core` 已有的 `solon-config-yaml` 加载。
- `AgentI18n.fmt` / `format` 只支持命名占位符：`fmt(locale, key, name, value[, name2, value2[, name3, value3]])` 与 `fmt(locale, key, Map)`，删除了 `Object...` 序号版本（4.2.0 新增未发布，不留别名）。
- **删除** `AgentSystemPrompt.getLocale()`：模板自带语言不可配置，会让 `options.locale` 之外多出一个语言来源。自定义模板若要按语言渲染，直接读 `trace.getOptions().getLocale()`。
- 恢复持久化会话时，智能体会在准备阶段自动登记快照中携带的语言（`AgentI18n.registerLocaleOf`），旧消息中的标记可被识别，无需手动调用 `registerLocale`。
- **删除** `ReActSystemPromptCn/En` 和 `TeamSystemPromptCn/En`：它们唯一的作用就是让模板自带语言。默认模板为 `ReActSystemPromptDefault` / `TeamSystemPromptDefault`，语言由 `locale(...)` 指定。迁移：`systemPrompt(ReActSystemPromptEn.getDefault())` → 默认模板 + `locale(Locale.ENGLISH)`。
- `FeedbackTool` 的 public 常量保留，新增按 Locale 获取描述的方法。
- `PlanTalent` 的工具改为按 locale 用代码构建。中文下的工具名、参数、schema 和描述与原来一致。
- `VectorStoreCompressionStrategy` 的 `recall_history` 工具改为按语言用代码构建（去掉了 `@ToolMapping` 注解）：描述、参数描述和返回文案都使用同一语言；中文下的 schema 与原注解版完全一致。`getToolAry()` / `getToolMap()` 返回默认语言的工具。新增 `recall(Locale, ...)` 重载。
- 团队成员未显式设置 locale 时继承团队语言（以前成员各用自己的默认语言）。
- 团队记录中的 `[Skipped] ...` 跳过说明和"成员没有返回文本"的提示改为按团队语言输出（`[Skipped]` 标签保持不变）；默认中文下这几条从英文变为中文。`[Routing]`、`[Terminated]` 等诊断记录仍为英文。
- 不指定 locale 时，生成的提示词与 4.1 逐字一致，由 `PromptGoldenTest` 的快照保证。

## 6. 测试与覆盖率

`features.ai.i18n` 包下的用例覆盖：

| 用例 | 保证什么 |
|---|---|
| `PromptGoldenTest` | 中英文主提示词、协议指令、工具描述的逐字快照（`src/test/resources/i18n-golden`，`-Dgolden.update=true` 重生成） |
| `RuntimeRenderGoldenTest` | 主提示词之外所有拼装点的渲染快照（计划看板 / Talent、反思提示、Simple 提示词、主管输入、A2A / Swarm / Hierarchical / ContractNet 各阶段、压缩请求与截断标记），`runtime_*.txt`。与 `PromptGoldenTest` 一起覆盖每个由代码补分隔符的调用点 |
| `I18nMessagesSnapshotTest` | 全部文案加载后的逐字快照（`messages_zh.txt` / `messages_en.txt`），与资源书写格式无关 |
| `I18nResourceLintTest` | yml 书写格式、值无首尾空白与空白标记符、跨语言 key 与占位符一致、花括号白名单、英文包无中文、无同名 `.properties` 遮蔽、源码调用点的变量名 |
| `AgentI18nTest` | 语言解析与兜底、缺 key 抛异常、命名占位符与 `fmt` 各重载 |
| `AgentI18nCoverageTest` | 默认语言、缓存、Prompt 语言标签的各种取值、占位符边界与名字规则、线性耗时、变量名重复、覆盖值原样使用、覆盖工厂返回 null / 抛异常 / 回调 AgentI18n、加载期间清空缓存 |
| `ReActRuntimeI18nTest` / `CompressionI18nTest` | ReAct 运行时提示与压缩链路：英文下不含中文 |
| `TeamBaseI18nTest` / `TeamProtocolI18nTest` / `TeamLocaleInheritTest` | 团队提示词与七个协议；成员继承团队语言 |
| `I18nKeyScenarioTest` | 只在异常 / 边界分支出现的文案（模型错误、自动反思、计划工具边界返回、HITL 批量 / 跳过 / 拒绝、拦截跳过、成员无内容、协议拒绝与守卫、压缩异常分支），中英双语，断言输出等于该 key 的文案 |
| `I18nKeyCoverageTest` | **key 覆盖率 100%**：逐个运行上述行为用例，记录产品代码（不含测试代码）实际读取的 key，要求中英两种语言下每个 key 都被读取过；新增 key 而没有用例走到时失败并列出缺失的 key。新增行为用例类时要登记到其 `SUITES` |
