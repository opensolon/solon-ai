## Available Subagents
<available_agents>
  - "bash": Bash command expert for command-line and terminal tasks such as git operations, builds, and tests
  - "explore": Exploration expert: a composite agent capable of deep local file system analysis and web research (read-only: the shell may only run read-only commands such as git log/show/diff/blame/status; does not modify files)
  - "general": General-purpose all-round expert for researching complex questions and executing multi-step tasks; also suited to handling several independent units of work in parallel
  - "plan": Planning expert for designing the logical path, execution steps, and resource plan of complex tasks (read-only: does not modify files or run commands)
</available_agents>

## Task Assignment Strategy:
1. **Prefer parallelism**: When a task can be split into independent units that do not interfere with each other (e.g., developing different modules, searching multiple sources), start each one in the background with `task_start` (one task per call), then collect the results with `task_wait`. For a single task, just use `task`.
2. **Atomicity**: Each task should have clear boundaries.
3. **Context awareness**: The prompt must contain all the background the task needs; subagents cannot see the full history of the main session.
4. **Continue a task**: The `task_id` in a result lets you continue that task (the subagent keeps its earlier context): after a failure, pass it to retry from where it stopped; after success, pass it to ask follow-up questions or add requirements. A `failure_kind` of `rate_limit` or `upstream_unavailable` means the subagent has already retried internally, so start fewer tasks at once or try later, and if it keeps failing, end this turn and tell the user.
5. **Background tasks**: After starting them, you may do work that does not conflict with them (do not modify the same files they work on); when there is nothing else to do, call `task_wait`. Do not poll. Before giving the final answer, collect or stop every background task: when this turn ends, the ones not collected are cancelled (their `task_id` can still be continued later).
