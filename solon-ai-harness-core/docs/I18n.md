# harness 国际化（i18n）

从 4.2 起，harness 面向模型和用户的文案（协议指令、talent 指令与工具返回文案、命令输出、HITL 理由、取消消息、内置子代理、goal 提示词等）都放在资源包里，内置中文（zh）和英文（en）。不配置语言时，输出与 4.1 逐字一致（中文）。

智能体本身的国际化（主提示词、团队协议、压缩）见 [solon-ai-agent/docs/I18n.md](../../solon-ai-agent/docs/I18n.md)。两者共用 `solon-ai-core` 的 `org.noear.solon.ai.i18n.AiI18n`：默认语言、覆盖工厂、已知语言全局只有一份。

## 1. 指定语言

```java
// 引擎实例的默认语言（不设则用全局默认语言，即中文）
HarnessEngine engine = HarnessEngine.of(workspace, ".solon/")
        .locale(Locale.ENGLISH)
        ...
        .build();

// 单次输入指定语言（优先于引擎）
engine.handle(HarnessInput.of(session, "list the files").locale(Locale.ENGLISH));
host.submit(tenant, sid, HarnessInput.of("list the files").locale(Locale.ENGLISH));

// 全局默认语言（智能体、harness、talent 共用）
AiI18n.setDefaultLocale(Locale.ENGLISH);
```

建议：一个引擎服务一种界面语言时，只在引擎上配置 `locale`；同一引擎要服务多种语言时，每次输入带上用户的语言。

## 2. 语言从哪里来

### 2.1 一次输入：输入优先，引擎实例兜底

```
HarnessInput.locale > HarnessEngine.Builder.locale > AiI18n.getDefaultLocale()（默认中文）
```

- `engine.localeOf(input)` 按上面的顺序取值（前两个都没有时为 null，即用全局默认语言）。
- 受理时取一次，然后下传到这一轮的整条链路：本轮请求的 `options.locale`（协议指令、talent 指令、工具参数 `__locale`、HITL 理由、中断时写入的取消消息、子代理）、命令输入 `input.getLocale()`、忙碌 / 待审批提示、附件前缀与默认提问、命令被作用域拒绝的说明。
- 不回写到输入：进积压时只保存输入自己指定的语言，续发时再按这个规则取一次。

### 2.2 后台轮次与门面 API

goal、loop 的后台轮次由调度发起，没有用户输入可取语言。

**goal 记住自己的语言**：创建时把用户的语言记在目标上（`GoalSpec.locale`；`/goal` 命令取命令上下文的语言 `input.getLocale()`），以语言标签随会话快照持久化（投影字段 `locale`，重启恢复后不丢）。每轮取一次「目标的语言，没有时 `engine.getLocale()`」，提示词按它渲染，并作为 `GoalExecutor.handle(sessionId, prompt, locale)` 的第三个参数交给执行器；缺省执行器与 `HarnessHost` 的执行器把它写进本轮输入（`HarnessInput.ofProgram(...).locale(locale)`），所以这一轮的协议指令、工具文案、工具参数 `__locale` 与提示词是同一种语言。自定义执行器也应这样做。

**loop 也一样**：任务的提示词虽然是用户原文，但定时轮次同样没有输入可取语言，所以创建时把语言记在任务上（`LoopSpec.locale`；`/loop` 取命令上下文的语言，`loop_add` 取工具参数 `__locale`），以语言标签随任务持久化（键 `locale`，缺失 = 跟随引擎，旧数据即如此）。每一轮取一次「任务的语言，没有时 `engine.getLocale()`」，作为 `LoopExecutor.handle(sessionId, prompt, locale)` 的第三个参数交给执行器；缺省执行器与 `HarnessHost` 的执行器把它写进本轮输入。

| 位置 | 语言 |
|---|---|
| goal 每轮提示词与这一轮的输入、写入“上一轮结果”的系统说明 | 目标的语言 > `engine.getLocale()` |
| goal 门面 `update` 的“终态不可编辑”说明 | `GoalPatch.locale` > 目标的语言 > `engine.getLocale()` |
| goal 门面 `create` 的“已有进行中的目标”说明 | `GoalSpec.locale`（发起创建的人）> `engine.getLocale()` |
| loop 后台轮次与这一轮的输入、`lastResult` 里的说明 | 任务的语言 > `engine.getLocale()` |
| loop 门面 `schedule` / `update` 的参数错误说明、`/loop` 回执 | `LoopSpec.locale` / `LoopPatch.locale` / 任务的语言 > `engine.getLocale()`；命令回执取命令上下文的语言 |
| core 内置命令回执（`/model` 等）、Markdown 自定义命令没写 description 时的兜底描述 | 命令上下文的语言 > 默认语言 |
| queue 门面 `enqueue` 的“队列已满”说明 | `engine.localeOf(input)` |
| 未消费的插话转入积压 | 带上本轮轨迹的语言，续发时与原来那一轮一致 |

目标未指定语言（编程创建时没调 `locale`、升级前保存的目标）时不写这个字段，始终跟随当前的引擎语言；任务同理（键 `locale` 缺失 = 跟随引擎）。

**语言可以随更新换**：`locale` 是目标／任务的属性，不是界面的属性，但创建之后仍可改。`GoalPatch.locale`、`LoopPatch.locale` 就是改它的入口；不调用这个方法（或传 null）表示保持现有语言，从来不会把语言清掉——目标／任务一旦有了语言，就一直用它，想回到「跟随引擎实例的语言」只能重建。宿主把用户当前的界面语言原样传进来即可：Web 端的 `/web/chat/loop/update`、`/web/tasks/update` 都接受 `locale` 参数（不传或传空串 = 不改），面板编辑时前端会带上 `currentUiLocale()`，所以用户在界面上切了语言再编辑一次，那个目标／任务就换过来了。

没调 `locale` （或创建时就没指定）时的解析链始终是：**目标的语言／任务的语言 > `engine.getLocale()` > `AiI18n.getDefaultLocale()`（进程级全局默认语言）**。

### 2.3 续流：语言属于一轮

语言在一轮开始时定一次，记在这一轮自己身上（原始提示词的 `__locale` 属性，随会话快照保存）。续流（`decide`、`resume(true)`、`/continue`、`engine.resume()`）不是新的一轮，默认沿用原来那一轮的语言，会话从存储重新加载后也一样。所以 `decide` 没有语言参数。

- 续流输入显式带了语言时，以输入为准。
- 原来那一轮没有留下语言（升级前保存的旧会话、从没跑过）时，用引擎语言。
- 续流被“会话忙”拒绝时，提示按 `engine.localeOf(input)` 输出（它回应的是这次输入）。
- 规则在智能体层：`ReActTrace#getRunLocale()` 读原来那一轮的语言，`ReActRequest` 在应用请求选项之前先定好本轮默认语言。新任务用智能体配置的语言，不再沿用同一会话上一轮的语言。

### 2.4 每类文案用什么语言

| 类别 | 语言来源 |
|---|---|
| 指令、才能标题行 | `prompt.locale()`（prompt 可能为 null 时用 `AiI18n.localeOf(prompt)`）；标题行由 `Talent#description(Prompt)` 提供 |
| 工具返回值 | 工具方法参数 `String __locale`（工具上下文注入，`AiI18n.toLocale(__locale)` 转换），没有时用默认语言 |
| 给用户看的输出 | 输入的生效语言（§2.1） |
| 参与逻辑判断的标记、关键词 | 生成时用当前语言；识别时匹配所有已知语言（§5） |
| 整份提示词文件（内置子代理） | 按语言分文件（§4） |
| 只属于一个会话的产物（如向量归档） | 本轮（trace）的语言 |
| 多个会话共用的产物（如 `CODE.md`） | 已有产物的语言优先，新建时用请求语言（§2.5） |

### 2.5 才能不保存语言

语言只分两层：默认层（`AiI18n` 全局默认语言；引擎、智能体 Builder 上的 `locale`，只在请求没指定时生效）和请求层（`HarnessInput.locale` → `options.locale` → `prompt.locale()` / `__locale`）。才能没有语言设置，需要语言时从 prompt 或 `__locale` 取。

- `CodeTalent`：指令与结论按请求语言。`CODE.md` 是工作区里各会话共用的文件：已存在时把首行与各已知语言的标题（`code.md.title`）逐字比对，匹配到哪个就沿用哪个语言；不存在或对不上（被手工改过）时按请求语言生成。这样不同语言的会话不会来回改写它，升级前生成的中文文件也保持中文。**想换语言：删掉 `CODE.md`，下一轮按请求语言重新生成。** 显式初始化用 `init(cwd, locale)`（`init(cwd)` 已过时，按默认语言）。
- `VectorStoreCompressionStrategy`（agent）：描述、指令、工具按请求语言，归档与归档通知按 trace 语言。

## 3. 资源包

| 模块 | 内容包 | 文件 | 门面 / key 常量 |
|---|---|---|---|
| harness-core | `solon-ai-harness-core.i18n.harness` | `solon-ai-harness-core/i18n/harness*.yml` | `HarnessI18n` / `HarnessI18nKeys` |
| goal | `solon-ai-harness-goal.i18n.goal` | `solon-ai-harness-goal/i18n/goal*.yml` | `GoalI18n` / `GoalI18nKeys` |
| loop | `solon-ai-harness-loop.i18n.loop` | `solon-ai-harness-loop/i18n/loop*.yml` | `LoopI18n` / `LoopI18nKeys` |
| queue | `solon-ai-harness-queue.i18n.queue` | `solon-ai-harness-queue/i18n/queue*.yml` | `QueueI18n` / `QueueI18nKeys` |
| steer | `solon-ai-harness-steer.i18n.steer` | `solon-ai-harness-steer/i18n/steer*.yml` | `SteerI18n` / `SteerI18nKeys` |
| talent-todo / web / lsp | `solon-ai-talent-<名>.i18n.<名>` | `solon-ai-talent-<名>/i18n/<名>*.yml` | `TodoI18n` / `WebI18n` / `LspI18n` 及对应 `*Keys` |

- 默认文件（无后缀）是英文，作为所有语言的兜底；`_zh` 是中文。
- 书写规则、加载顺序、扩展新语言、覆盖工厂（`AiI18n.setBundleFactory`）都与智能体相同，见 [agent I18n §2](../../solon-ai-agent/docs/I18n.md#2-资源包)。
- 工具描述与参数说明**不做国际化**：它们只给模型看、界面上不显示，留在 `@ToolMapping` / `@Param` 注解里（单一语言，与 4.1 一致）。资源里出现 `tool.` 开头的 key 时 lint 报错。工具的**返回文案**会显示在界面上，仍按请求语言输出（工具方法末尾声明 `String __locale`）。

二期已接入 Terminal、Skill、Code、Memory、Gateway（talent cli / code / memory / gateway），资源与门面同上（`CliI18n`、`CodeI18n`、`MemoryI18n`、`McpGatewayI18n` / `OpenApiGatewayI18n` / `ToolGatewayI18n`）。

## 4. 内置子代理

- `META-INF/solon/ai/harness/agents/*.md` 是中文版，也是兜底。
- 其它语言放在 `META-INF/solon/ai/harness/agents-i18n/<名字>_<语言>[_<国家>].md`，内置 explore、bash、general、plan、git-summary 的英文版。查找顺序：语言_国家 → 语言 → en。
- 只替换 description 与正文，工具、权限等配置以基础文件为准，所以各语言行为一致。
- 只作用于引擎内置的定义；工作区 / 用户挂载里的同名子代理、运行时注册的子代理原样使用。
- 子代理清单按请求语言列出，委派时按主代理的语言取提示词。入口：`engine.localizeAgent(def, locale)`、`engine.getAgentBuilderOrNil(session, name, model, locale)`。
- 直接选中的子代理（`selectedAgent`、`@子代理`）按本轮语言取提示词：引擎先定本轮语言（续流沿用被中断那一轮的，读该代理自己的轨迹），再按它构建代理，提示词与协议指令同一语言。入口：`engine.getAgentOrMain(session, name, locale)`。

## 5. 跨语言识别的标记

会话可能来自其它语言（旧会话、中途换语言），所以下面这些识别时匹配所有已知语言：

| 判断 | 入口 | 资源 key |
|---|---|---|
| 中断补写的取消消息 | `InterruptPlan.isCancelText(text)` | `run.cancelled` |
| 插话前缀 | `SteerProtocol.textOf(message)`（取最长匹配） | `steer.prefix` |
| 执行型目标的关键词 | goal 内部判断 | `goal.action_keywords` |

## 6. 对外 API 变化（均为 4.2.0 新增、未发布，不留别名）

| 原来 | 现在 |
|---|---|
| `InterruptPlan.CANCEL_TEXT` | `InterruptPlan.cancelText(AgentSession)`（另有 `cancelText()`、`cancelText(Locale)`）、`isCancelText(String)` |
| `SteerProtocol.PREFIX` | `SteerProtocol.prefix(AgentSession)`（另有 `prefix()`、`prefix(Locale)`；结尾空格由代码补），识别用 `textOf` |
| `CommandDispatcher.COMMAND_*_HINT` | `unavailableHint(name)`、`unavailableHint(name, locale)`、`disabledHint(name)`、`disabledHint(name, locale)` |
| 原 `_agent_locale` 工具上下文键 | `AiI18n.ATTR_LOCALE`（`__locale`），同时写入 `Prompt.attrs` 与工具上下文 |
| `CommandValidator.failurePrefix` / `whenNothingToRun` | 带 `Locale` 参数 |

纯新增：

- `HarnessEngine.Builder.locale(Locale)`、`engine.getLocale()`、`engine.localeOf(HarnessInput)`、`engine.localeOf(AgentSession)`。
- `HarnessI18n.localeOf(AgentSession)`：宿主只需要"这个会话的文案用什么语言"时用它。
- `Command.examples(Locale)`：默认返回 `examples()`；示例里有自然语言文本的命令按语言覆写，`/help` 用它。
- `GoalValidator.validate(condition, workDir, Locale)`：默认方法，没有覆写它的自定义验证器照常工作。
- `LoopArgumentException`：loop 参数校验的异常，携带 key 与变量；`getMessage()` 为默认语言，`getMessage(Locale)` 按指定语言。
- goal / loop / web / todo / lsp 等工具方法末尾加了 `String __locale` 参数（由框架从工具上下文注入，不进 schema）。参数更少的旧签名不保留：直接调用工具方法时末尾传 `null`（默认语言）。

宿主手上的入口都收在"给会话"这一档，不必自己取轨迹再取语言：

```java
// 取消回执：与框架落库的取消消息同一语言（本轮的语言）
String cancelText = InterruptPlan.cancelText(session);

// 引擎侧同理（会话没有轨迹时退回引擎实例的语言）
Locale locale = engine.localeOf(session);

// 插话前缀：回放/识别场景用默认语言即可
String prefix = SteerProtocol.prefix();
```

需要指定语言时都保留了同名重载（`cancelText(Locale)`、`prefix(Locale)`、`unavailableHint(name, Locale)` 等）。

## 7. 测试

每个接入模块都有同一套用例：

| 用例 | 保证什么 |
|---|---|
| `XxxRenderGoldenTest` | 渲染快照：`testZh`（默认语言）/ `testZhExplicit`（显式中文）/ `testEn`。中文快照用改造前的代码生成，保证中文逐字不变 |
| `XxxI18nLintTest` | 资源书写格式、中英 key 与占位符一致、key 常量与资源一致、产品代码无 key 字面量、`fmt` 变量名与占位符一致（`I18nLint`） |
| `XxxI18nCoverageTest` | key 覆盖率 100%（中英两种语言，`I18nKeyCoverage`）。读取覆盖：每个 key 都被产品代码读到过（测试类即使与产品同包也不算）。断言覆盖：逐个 key、逐个语言变异后重跑读到它的用例，至少一个失败。新增行为用例类时要登记到 `SUITES` |
| `XxxI18nScenarioTest` | 只在低频分支出现的文案（core / goal / steer / todo）。英文期望值用 `FrozenMessages`（审校过的文案快照），不要用 `XxxI18n.get` 现取，否则断言覆盖不过 |
| `HarnessI18nMessagesSnapshotTest` | harness-core 全部文案的逐字快照（`messages_zh.txt` / `messages_en.txt`），供 `FrozenMessages` 读取 |
| `HarnessEngineLocaleTest` | 语言来源：引擎语言、输入覆盖、后台轮次、不回写输入、续流沿用原语言（含会话重新加载与审批决定） |

测试工具在内部模块 `solon-ai-testkit`（`org.noear.solon.ai.i18n.testkit`，不发布），接入模块以 `scope=test` 声明它的依赖（版本 `${project.version}`）。插件模块的命令测试替身 `Fakes` 在 `solon-ai-harness-testkit`（同样不发布）。不再使用 test-jar。

生成快照：

```bash
# 只重生成英文快照（中文是基线，不要覆写）
mvn -pl solon-ai-harness-goal test -Dtest='GoalRenderGoldenTest#testEn' -Dgolden.update=true
```
