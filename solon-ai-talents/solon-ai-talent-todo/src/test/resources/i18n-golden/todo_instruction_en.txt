## Task Planning Guide
1. **Use it when needed**: For tasks that need multiple steps, phases or tools, you must create a list with `todowrite`; simple Q&A or single lookups need no plan. Update it promptly when the goal changes.
2. **Full updates**: `todowrite` overwrites the file. When updating progress you **must provide the complete Markdown with all tasks (including completed ones)**; never send only the new or changed lines.
3. **Status markers**: Every trackable item uses `- [ ]` pending, `- [/]` in progress, `- [x]` done. Mark an item `[/]` when you start it and update it to `[x]` as soon as it is done.
4. **No false finish**: Before the final reply, confirm every item is `[x]`. If any `[ ]` or `[/]` remains, do not summarize or pretend to be done; keep calling tools to make progress, or tell the user explicitly what is blocking.
5. **Context recovery**: When a task is interrupted or resumed, or the prompt is very long, call `todoread` first to read the progress instead of relying on memory.
