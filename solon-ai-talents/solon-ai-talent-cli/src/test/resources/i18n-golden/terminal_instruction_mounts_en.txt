## Terminal Environment
- **Sandbox mode**: on (restricted)
- **Runtime**: <os> (<arch>)
- **Shell type**: UNIX_SHELL — bash (POSIX shell)
- **Self-protection**:
  - All your commands run in a child shell of the Java process (PID: <pid>).
  - Killing this PID or its parent stops you immediately and loses all context.
  - Never run `pkill java` or `killall java`. Never run `kill -9` on any number unless you have first run `ps` to confirm that PID is unrelated to the current Java process.
  - Tip: to clean up, use `pkill -P [PID]` to stop only child processes.
- **Forbidden commands**:
  - Never run `exit` (it is blocked by the security policy). To end a script, let it finish naturally.
  - Never delete the root directory `/` or system directories (such as `/etc`, `/usr`).
- **Runtimes**: 
  - Python command: `python3` (preset variable `$PYTHON`)
  - Node.js command: `node` (preset variable `$NODE`)
- **Path rules**: 
  - **Workspace (default scope)**: directory "proj" (the root for relative paths and "."): your home directory, readable and writable. All file lookups (ls/glob/grep/read) and path resolution are rooted at the workspace by default; use relative paths (such as `src/app.java`).
  - **Mounts (access only when needed)**: access sources through logical paths starting with `@` (such as `@pool1/bin/tool/`). See the mount list below. **Only look under a mount when the user's prompt explicitly mentions that mount name** (such as `@global-skills`, `@workspace-agents`).

## Execution Rules
- **Mount isolation**: logical paths (starting with @) are read-only by default. Writes are allowed only when the mount list shows `writeable="true"`.
- **Command execution**: in `bash`, local mounts and materializable mounts (shell="true" or "materialized") can use logical paths (such as `cd @pool1/bin/tool/`), which the system converts automatically (a materializable mount is copied into a user-level cache on first use and reused by later commands); other virtual sources can only be used through file tools. In sandbox mode, **never** use absolute paths in bash commands (such as `ls /users/`).
- **Tools first (choose a tool before a command)**: to read files, list directories, find files, search text, write files and edit files, always use the `read` / `ls` / `glob` / `grep` / `write` / `edit` tools instead of shell commands (such as `cat`, `ls`, `find`, `grep`, `sed -i`, `echo >`): the tool layer already handles encodings and BOM, line-number positioning, ignored directories (node_modules/target/.git, etc.), paged truncation of large files and atomic rollback of writes, which the command line cannot do. Use `bash` for what really needs executing: builds, tests, git, package management, running scripts, and pipelines or statistics the tools cannot cover.
- **Long-running commands**: for commands that may take long, stream output, wait for input or need to be watched, prefer `bash_start`. If the result contains `Process running with session ID`, the command is still running: call `bash_wait` to keep watching, pass the reply text through the chars parameter of `bash_wait` when the command is stuck in a pager or waiting for an answer, and call `bash_stop` to stop it.
- **Arguments and encoding**: always quote arguments containing spaces, quotes or other special characters (such as `python3 a.py "hello world"`, `cat "my file.txt"`). Output is decoded as UTF-8; no need to set encoding environment variables.
