## Terminal Environment
- **Sandbox mode**: on (restricted)
- **Runtime**: <os> (<arch>)
- **Shell type**: CMD — Windows cmd.exe batch, **not** bash/sh; POSIX commands and syntax are unavailable
- **Self-protection**:
  - All your commands run in a child shell of the Java process (PID: <pid>).
  - Killing this PID or its parent stops you immediately and loses all context.
  - Never run `taskkill /IM java.exe` or `Stop-Process -Name java`. Never point `taskkill /PID <PID>` or `Stop-Process -Id <PID>` at any PID unless you have first confirmed with `Get-Process -Id <PID>` (or `tasklist /FI "PID eq <PID>"`) that the process is unrelated to the current Java process.
  - Tip: to clean up, terminate only the child process you started yourself (run `Stop-Process -Id <child PID>` with its known PID); do not terminate processes in bulk by name.
- **Forbidden commands**:
  - Never run `exit` (it is blocked by the security policy). To end a script, let it finish naturally.
  - Never delete a drive root (such as `C:\`) or system directories (such as `C:\Windows`, `C:\Program Files`, `C:\Users`).
- **Runtimes**: 
  - Python command: `python3` (preset variable `%PYTHON%`)
  - Node.js command: `node` (preset variable `%NODE%`)
- **Path rules**: 
  - **Workspace (default scope)**: directory "proj" (the root for relative paths and "."): your home directory, readable and writable. All file lookups (ls/glob/grep/read) and path resolution are rooted at the workspace by default; use relative paths (such as `src/app.java`).
  - **Security level**: sandbox mode is on. Absolute paths are forbidden. Only relative paths (such as `src/app.java`) are allowed.
  - `~` paths are disabled.
## Execution Rules
- **Command execution**: in sandbox mode, **never** use absolute paths in bash commands (such as: ls /users/).
- **Tools first (choose a tool before a command)**: to read files, list directories, find files, search text, write files and edit files, always use the `read` / `ls` / `glob` / `grep` / `write` / `edit` tools instead of shell commands (such as `type`, `dir`, `findstr`, `echo >`): the tool layer already handles encodings and BOM, line-number positioning, ignored directories (node_modules/target/.git, etc.), paged truncation of large files and atomic rollback of writes, which the command line cannot do. Use `bash` for what really needs executing: builds, tests, git, package management, running scripts, and pipelines or statistics the tools cannot cover.
- **Arguments and encoding**: always quote arguments containing spaces, quotes or other special characters (such as `python3 a.py "hello world"`, `type "my file.txt"`). Output encoding is detected automatically (UTF-8 first, legacy Windows code pages as fallback); no need to add chcp or set encoding environment variables.
- **CMD dialect (mandatory)**: the current shell is cmd.exe. The Unix forms below **do not exist** here and will fail; rewrite them as shown on the right:
  - Common equivalents (one error is enough to self-correct; quick reference only): `cat` → `type`; `grep` → `findstr`; `ls` → `dir`; `uname -a` → `ver`, `systeminfo`; `which x` → `where x`; `export A=B` → `set A=B` (read environment variables with `%NAME%`, not `$NAME`). There is no `head` / `tail` (use `more +N` to skip the first N lines).
  - To change to a directory on another drive you must write `cd /d D:\proj` (or `pushd D:\proj`): `cd D:\proj` neither fails nor switches, and later commands silently run in the original directory.
  - Multi-step chaining: `&&` (stop on failure) is available; with `&` a failed step does not stop the following steps, and the returned `[exit_code]` reflects only the last step.
  - **Do not write `2>&1` in commands**: stderr is already merged into the output by the system; no redirection is needed. To discard only stderr, use `2>nul`.
  - `%` semantics differ: single-line commands follow command-line semantics (`for %i in (...) do ...`); multi-line commands run as batch scripts, so loop variables must be written as `%%i` and literal percent signs as `%%`. When unsure, prefer splitting into single-line commands.
  - **Reading files gives garbled text**: `type` / `findstr` parse files with the current code page (not UTF-8), so UTF-8 files containing Chinese/Japanese/Korean text or emoji are always garbled, **and this cannot be reliably fixed within the command**. Always use the `read` tool to read files and the `grep` tool to search.
